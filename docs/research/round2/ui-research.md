# 白泽 Baize Analytics：第二轮 UI/UX 研究与实施建议

核验日期：2026-10-10（UTC）  
代码基线：main `f4dbbccb4ba4e37c40bb0a7d68265d3b32d44030`，提交时间 2026-10-10 18:14:54Z。  
范围：现有产品改进设计，未修改业务代码、未注册账号、未新建网站、未运行 CI。

## 结论

白泽当前最值得做的不是增加视觉装饰，而是让已有能力按用户任务组织起来。建议保留现有绿色品牌、真实数据水位、覆盖率、隐私边界和 AI 证据，把它们整理成“找得到、看得懂、可核验”的分析工作台。

五项优先改善：
1. 把 38 个同级入口重组为任务分组，支持真正的 URL 导航和历史恢复。
2. 重做总览主次层级：固定核心指标 → 主趋势 → 来源/页面分解，常显筛选和比较口径。
3. 补齐响应式、键盘、文字对比和图表替代信息，建立可复用 UI 基础组件。
4. 把加载、无结果、未接入、聚合中、部分不可用、请求失败分开表达。
5. 将日常分析与管理配置分层，AI 默认先问数，连接器与危险操作进入明确的设置流程。

这里的建议是独立设计判断；竞品功能及画面事实另行列明，不能把“竞品这样做”当作白泽已通过可用性验证。

## 2. 竞品模式：取其任务组织，不照搬复杂度

### Plausible

**官方事实 / 桌面观察**
- 官方以单一主看板为核心，顶部指标可切换主图；日期、筛选、实时入口靠近站点上下文。
- 公开演示首屏是 6 个紧凑指标、一张主趋势，下方来源与页面两列；每个分解卡内用少量 tabs，而不是每个维度都占一个主导航。
- 官方文档说明未完成时间段用虚线；对比可选择上一期间、去年同期或自定义，且允许对齐星期。
- 行点击可应用筛选，演示的来源和页面链接含筛选参数。

**对白泽的建议**
- 学习首屏优先级、行到筛选的连续性、未完成时间段的诚实表达。
- 白泽包含 SEO、AI、运维，不适合硬塞成“所有功能一页”；使用少量任务分组更合理。
- “有快捷键”和“图表有 tooltip”都不等于通过无障碍。

来源：[官方看板说明](https://plausible.io/docs/guided-tour)、[时间比较](https://plausible.io/docs/compare-stats)、[公开演示](https://plausible.io/plausible.io)。

### Umami

**官方事实 / 官方截图观察**
- 当前文档明确覆盖 Umami v3；报告按 traffic、behavior、growth 组织，日期和筛选可跨报告应用。
- 官方截图为顶部指标、主图、页面/来源两列明细；高价值汇总先出现。
- 筛选可由 Filter 或概览行进入，当前条件显示在页顶。
- Share URL 可明确选择可见报告范围；说明“只读分享”需要让受众知道实际会暴露什么。

**对白泽的建议**
- 学习稳定的全局上下文和模块分组。
- 不在这一轮加入可拖拽自定义看板；先把默认看板做好。
- 不把 Cloud 新特性或官网营销描述无条件当成所有自托管版本的能力。

来源：[v3 文档](https://docs.umami.is/docs)、[Insights](https://docs.umami.is/docs/insights)、[Filters](https://docs.umami.is/docs/filters)、[分享范围](https://docs.umami.is/docs/enable-share-url)、[官方产品截图](https://docs.umami.is/images/docs/screenshot.png)。

**官方事实 / 桌面观察**

- 首屏 6 个指标卡带小趋势，主趋势下方为来源/页面分解。观察到卡片级骨架加载，然后填充真实数据，未把加载图视为错误。

**官方事实 / 文档截图观察**

## 3. 白泽当前具体问题

以下为源码事实及其 UI 风险，不等于生产实例已复现。

### 3.1 信息架构

- `main.tsx:96` 定义 38 个同级 tabs；收入、实时、采集细项、管理、SEO、AI 混排。
- `style.css` 的桌面侧栏宽 220px、独立纵向滚动；≤850px 变为普通块，38 个入口改为横向滚动。
- `App` 以 `useState('overview')` 维护 tab；该入口文件未见 pushState、replaceState 或 popstate。复制 URL、刷新、返回/前进无法从此实现恢复当前视图。
- 站点分组、语言、站点选择及添加按钮都在导航前，小屏首屏可能被控件占据；需要运行时核验而不是只量总宽度。

### 3.2 看板主次

- 总览 KPI 从 totals/summary 的对象条目展开，缺少显式主指标顺序和上限。
- 完整“收入币种与归因”块在主趋势之前；对未使用收入能力的站点仍会产生空表信息。
- 比较卡作为独立块放在趋势后，和主 KPI 距离较远。
- 日期始终显示开始/结束两个输入框，全局筛选放在折叠 details 内；折叠时没有常显条件标签。
- 泛型 Table 枚举返回字段来决定列，字符串不换行；错误码、内部字段名、长 URL 和数值可读性难稳定。

### 3.3 状态模型

- `View` 请求开始先 `setData({})`，但后续仍渲染表格；泛型 Table 空态统一提示“安装追踪代码后等待采集与聚合”。因此加载、请求失败、筛选无结果、未配置报表等会共享不准确的说明。
- 聚合自动更新、实时窗口不完整、历史保留边界等已实现，但表达分散。
- 实时页有 30 秒兜底刷新和 SSE；需要把连接状态与“没有新访问”区别开来，不能凭静默认为故障。
- 普通趋势图将 `r.pv || 0` 转为数字，应检查未知/null/未完成桶进入此组件时是否被画成零；这是待验证风险，不宣称已复现数据错误。

### 3.4 设置复杂度

- settings 在一张长页中组合站点信息、代码、保留策略、隐私采集、来源规则、GeoIP、实例级企业微信 SSO。
- AI 页对管理员先渲染完整模型配置，然后才出现日常问数。
- Google、SERP 等设置与日常报告在同页出现；应改成明确“未连接 / 已连接 / 配置不完整 / 同步失败”的摘要入口。
- 这不是要求默认打开采集或自动发送数据。用户必须仍能看见启用范围、数据目的地、外部费用和权限要求。

### 3.5 可访问性静态筛查

下列数值以源码中实色进行 sRGB 相对亮度计算，只用于定位；未检查浏览器最终 computed style、所有状态、主题、缩放、辅助技术，不能称为真实无障碍验收。

## 4. 可直接实施的布局规范

### 4.1 导航映射

保留现有业务组件与权限检查，先改变组织，不新增业务引擎。桌面固定显示“总览、实时”两项，以下为可折叠分组；默认只展开当前组。分组标题不是不可读的图标。

| 分组 | 映射现有入口 |
|---|---|
| 流量与内容 | 页面、来源、受众、文件下载、404 修复清单 |
| 行为与转化 | 事件、事件趋势、路径、目标、漏斗、留存、已识别用户、收入归因、实验 |
| 体验 | 性能、热图、回放 |
| 搜索与优化 | SEO、搜索关键词、SEO 转化对照、排名监控、建议复检 |
| AI 与报表 | AI、报表、告警、推送计划 |
| 设置 | 站点设置、历史导入、分享、成员、API 令牌、审计、任务恢复、隐私与数据、数据导出、通知渠道 |

- “设置”内再按“接入与连接 / 成员与共享 / 数据与隐私 / 运维”显示局部导航。实例 SSO、GeoIP 等标明“实例级”，避免误以为仅改变当前站点。
- 不改变现有角色授权；不可访问页面在直达 URL 时仍必须由后端拒绝。隐藏菜单不等于权限控制。
- 导航使用真实链接；组开关用 button + aria-expanded，不把普通网站导航做成需要复杂方向键语义的 menu。
- URL 表达站点、报告、日期和允许的筛选；例如结构可为 `/app/sites/:siteId/overview?... `，最终路由形式由工程确认。站点 ID/筛选解析使用白名单并验证；URL 不放密钥、分享密码或私人问句。
- 返回/前进恢复视图、日期和筛选；刷新不回总览；未知报告可恢复到允许页面并给说明。切站后不能残留旧站数据。
- “已保存报表”继续复用现有接口与 DSL。保存当前筛选的协议接线属于产品改进任务，不在 UI 层另造一套。

### 4.2 总览阅读顺序

1. 站点名称/域名 + 当前角色；页面标题“总览”
2. 日期快捷选择（今天、昨天、近7天、近30天、自定义）+ 可见时区 + 比较说明 + 刷新
3. 常显筛选条件标签；无筛选显示“全部站内流量”；外部数据页明确“不应用站内筛选”
4. 数据状态条：完整截至时间 / 当前覆盖 / 最近查询时间；异常才扩展说明
5. 4–6 个显式定义 KPI：访客、浏览量、会话、跳出率、平均时长；转化仅在口径和功能支持时加入
6. 一张主趋势；可选指标、时间粒度、前期线、图表/数据表切换
7. 两列：主要来源、热门页面，各默认 8–10 行，右上“查看全部”
8. 相关下一步：目标/性能/SEO 等最多两块；无数据按能力状态引导
9. 收入详细归因移到收入页；总览可显示按币种摘要与链接，但绝不混币相加

推荐指标卡：
- 第一行：名称及“指标定义”入口
- 第二行：主数值，数字采用 tabular-nums
- 第三行：相对上一期间的百分比及实际比较日期；无基线明确写“无可比较基线”
- 变化颜色与箭头/文本并用。“上升”不总是改善，跳出率等按指标语义解释；拿不准时用中性色
- 不支持指标用“—”和原因；零只代表已核验范围内的真零

趋势图：
- 计量数据默认直线连接，避免平滑曲线暗示不存在的中间形态。
- 当前未完成桶用明确样式和文字；缺失未知桶保持 null，不插补为零。
- 前期用虚线且带名称；不能仅靠绿色/红色区分。
- 保留现有原始表格能力，折叠为可发现入口；历史对照需提供“同一天、本地PV、历史PV”的等价表。
- 标注所选范围、实际可用范围、时区、单位及样本数（适用时）。静态图标题不代替数据说明。

### 4.3 尺寸、排版与视觉 token 建议

这些是新设计的起点，不是竞品测量值，也不是无障碍标准本身。

- 品牌主色继续 #166c52；白卡片、浅绿灰页面背景保留。色彩更多用在选中、状态、数据系列，不给每张卡不同渐变。
- 桌面主导航建议 224–240px，内容最大宽 1440px；主区左右留白 24–32px。
- 8px 间距体系，常用 8/12/16/24/32；卡片内边距 20–24px，手机 16px。
- 正文/主要控件 14–16px；辅助说明至少 12–13px，关键信息不用极浅小字。中文正文行高约 1.5–1.7。
- 页标题 28–30px，区标题 18–20px，指标 28–32px。控制字重层级，不依赖细字体。
- 表格主列左对齐、数值右对齐；日期和币种显式；长 URL 可换行或截断后有可键盘触发的完整内容，不使用仅 hover 才能获取的 tooltip。
- 表格默认精选稳定列，技术详情放“更多字段/查看详情”；不要用对象枚举作为最终用户表结构。
- 原生输入、select、textarea、details、链接、按钮统一焦点环；建议深色双层环，最终在实际相邻背景验证。
- 状态有文字和图标：已完成、聚合中、数据不完整、未连接、错误。提示不以黄色背景替代标题。

### 4.4 响应式

- ≥1200px：导航常驻，主图全宽，分解卡两列。
- 768–1199px：按可用宽度保留两列或转单列；数据量与字号不等比例缩小。
- <768px：一个有名称的“菜单”按钮打开导航抽屉；常用站点/当前报告仍可见。禁止把38项塞进横向长条。
- 手机 KPI 为两列；遇长数值、200%文本缩放可一列。主趋势约240–280px高，详细表可折叠。
- 日期与筛选控件换行；状态条可换行，不用横滚隐藏有效条件。
- 宽表只在自己容器横向滚动，提供表名和可见滚动提示，保证键盘可进入并滚动；页面本身不横滚。长表格有必要的二维结构时，不应把 WCAG Reflow 误读成禁止所有表格横滚。
- 抽屉开时焦点进入，Esc关闭，关闭后回菜单按钮；背景不能继续被误操作。当前组/当前项保持可见。
- sticky 顶栏只保留必要上下文，不能盖住焦点或挤占手机大半高度；滚动预留 scroll-padding。

## 5. 状态与文案规范

API事实优先，不能用客户端猜测新状态。后端缺字段时先显示“无法确认”并补协议，不编造完成率或剩余时间。

| 状态 | 推荐展示 | 主要动作 |
|---|---|---|
| 首次加载 | 同尺寸静态骨架 + “正在读取数据” | 必要时取消/离开；不要同时显示无数据 |
| 同一查询后台刷新 | 保留旧值，标“更新中”及旧值时间 | 重试；失败保留旧值并标明 |
| 切换站点/日期/筛选 | 清除不匹配旧值或明确新旧边界 | 不得将旧站数据冒充新查询 |
| 尚未创建站点 | 建站说明 | 添加站点（按权限） |
| 已有站点但未验证接入 | “尚未确认收到访问”及追踪接入步骤 | 查看代码、检查接入 |
| 已收到但未聚合 | “已收到数据，聚合中”+事实水位 | 自动更新；给管理员诊断入口 |
| 完整范围真零 | “该期间没有访问” | 更改日期 |
| 条件无匹配 | “当前筛选没有匹配结果”+常显条件 | 清除筛选 |
| 模式不支持 | “每日盐模式不支持跨日去重”等准确原因 | 指标说明；不要随意劝改隐私 |
| 超出保留范围 | “此范围的细分明细不可用” | 选可用日期；保留已有总量边界 |
| 部分覆盖 | 值旁标“部分数据”，不能生成确定变化结论 | 查看缺失范围/任务状态 |
| 外部来源延迟 | 最新可用日期、提供方、最后同步状态 | 扩大范围/同步，不能无限自动重试 |
| 401/403 | 会话过期/无权限 | 重新登录/联系管理员，避免当作空表 |
| 请求失败 | 当前卡片错误、简明原因、重试 | 不清空无关已成功卡片 |
| 后台任务失败 | 任务名、时间、影响、可用恢复操作 | 仅有权限者可重试；原始JSON在详情 |
| AI 不可回答/证据缺失 | 明确缺口，不生成图表或事实结论 | 调整范围/查看证据 |
| 实时连接恢复中 | 连接状态与最近成功更新时间 | 暂停/恢复；不能把离线解释为零在线 |

- 所有保存按钮都有正在保存/成功/失败状态，避免连续点击重复提交。
- 非紧急状态用 role=status；错误按需要 role=alert。不要每2秒把整页重新播报。
- 没有实际数据时不塞演示曲线。可提供明确标注、独立的示例说明，不能混入站点统计。
- 首次接入闭环可以复用已有采集/水位信息，但真正“验证成功”必须有后端证据；UI不能仅因用户复制代码就亮绿色成功。

## 6. 设置与 BYOK AI 的可落地流程

### 日常 AI 页

默认内容顺序：
1. 当前站点、日期、可发送的聚合范围
2. 问题输入、几个范围内可执行的示例问题
3. 模型状态摘要（已配置提供方/模型、预算提示、查看连接设置）
4. “查询并解释证据”
5. 回答、事实证据、限制、查询工具记录

只在未配置时显示接入引导；已配置不把完整密钥表单排在问数前。管理员可从明确按钮进入设置，普通分析者看见自己能做什么。保留发送前的目的地和数据范围提示；“BYOK”不得暗示本地推理。

### 连接器设置

每个连接器使用列表卡：
- 名称、用途、当前状态
- 最近成功同步时间、最新可用数据日期
- 只显示非秘密设置摘要
- 配置/验证/同步/断开分开操作
- 外部调用费用、访问范围、必要权限就近说明

密钥从不回显；不要为了“省一次点击”自动启用定时外发或扩大授权。保存成功不能伪称连通成功；模拟验证与真实提供方验证必须区分。

### 危险和实例级设置

- 数据删除、保留缩短、分享公开、令牌吊销独立危险区。
- 确认弹窗说清站点、范围、影响和能否恢复；不能只有泛化“确定吗”。
- 实例设置单独标记并做权限拦截，避免藏在每个站点长表单末尾。
- 单个表单按自然任务拆分，有本地成功反馈，不要提交一处导致整个设置页滚回顶部。

## 7. 五项实施工单与验收条件

### UI-1：任务导航与可恢复上下文（P1，先做结构）

**位置**：main.tsx App/tabs，style.css。  
**边界**：复用当前报告组件、权限、查询接口；不新增计费或权限模型。

**验收**
- 38 项全部有明确归属；默认导航不展示一列38项。
- 桌面/手机都能在可发现的路径进入 SEO、AI、任务恢复。
- 从页面报告设置日期/筛选，再进入来源，返回/前进/刷新均能恢复预期上下文。
- 直接打开无权限报告得到正确禁止状态；切站不存在旧站数据闪现。
- 关闭手机导航、取消添加站点，焦点和当前页面保持正确。

### UI-2：总览指标与筛选/比较重排（P1）

**位置**：main.tsx View/Comparison/Table，DashboardFilters.tsx，Charts.tsx。  
**边界**：先采用已有支持的比较与筛选，UI不得承诺尚未实现的同比、自定义算子。

**验收**
- 明确指标白名单、排序、单位与不支持状态。
- 主趋势出现在收入详细归因之前；无收入站点不被无关空表占满。
- 活跃筛选折叠后仍可见、可单项清除；日期、时区、比较范围一致。
- 来源/页面点击应用筛选只在后端已支持对应条件时启用。
- 未完成数据、无基线、多币种、每日盐模式不会生成伪零或错误增幅。
- 保存报表接收真实当前筛选的需求与产品协议改进联动，不引入第二套状态。

### UI-3：可访问 UI 基础与手机路径（P0 风险修复，可并行）

**位置**：style.css、所有原生表单、Charts.tsx、GeographyExplorer.tsx、AiEvidenceView.tsx。  
**边界**：优先语义 HTML；不以替换一整个组件库作为前提。

**验收**
- 在实际渲染中检测正文、表头、辅助文字及焦点/交互状态，普通文本达到4.5:1，大字及必要非文本对比按对应标准核验。
- 键盘完成导航、日期选择、应用/清除筛选、图表数据查看、表单提交/取消；无焦点陷阱。
- 有跳到主内容入口；页面标题与焦点更新有明确行为。
- 320、390、768、1280、1440px；200%文本缩放；400%浏览器缩放的代表页面检查。记录具体结果，不以单一宽度通过代替全部。
- 所有重要图表有范围/单位/文字摘要或等价数据表；地图下钻保留原生select替代。
- 对长中文、英文、超长URL、长错误文案、大金额和无数据做截图检查。
- 自动扫描之外至少做键盘人工检查；可用环境有屏幕阅读器时做NVDA/VoiceOver代表路径验证，未做则明示。

### UI-4：统一数据状态与接入反馈（P0 正确性）

**位置**：main.tsx View/Table、RealtimeSummary.tsx、StorageEvidence.tsx、各异步页面。  
**边界**：复用真实水位和状态，后端缺少接入健康字段则列为依赖，不编造检测结论。

**验收**
- 加载、请求失败、筛选无结果、未接入分别呈现，不同时出现矛盾提示。
- 单个卡片失败不清空无关成功卡；重试不会重复创建任务。
- 同查询刷新保留旧值且标时间；新查询不复用旧站/旧筛选值。
- coverage<1、保留边界、外部延迟和不支持模式均有准确文案。
- 可见状态变化能被辅助技术获知而不过度播报。
- 页面切换/刷新中取消请求，旧请求不能覆盖新结果；保留当前已有 AbortController 防护并回归测试。

### UI-5：设置分层与 AI 优先任务（P1）

**位置**：main.tsx settings/AIPanels/ExternalPanels，Connectors.tsx。  
**边界**：不自动启用采集、授权或外部发送，不改变 BYOK 安全策略。

**验收**
- 已配置AI站点进入页面直接看到问数，连接摘要可进入设置。
- 未配置/配置保存/真实验证成功/同步失败四种状态清楚区分。
- 管理员与分析者看到的操作符合权限；实例设置不冒充站点设置。
- 成功/错误反馈就近显示；表单有重复提交保护与未保存离开处理。
- 密钥、隐私、目的地、成本和不可恢复影响未因视觉简化被隐藏。
- 清理原始JSON默认展示，但保留可访问的技术详情用于诊断。

## 8. 验证方法与停止条件

建议先完成一条纵向路径：总览 → 日期/筛选 → 页面详情 → 返回总览，再把共同组件推广到 SEO 与 AI。不要一轮重写全部38页。

每次实施应交付：
- 改前/改后截图，注明提交、视口、数据场景
- 单元测试：URL解析、状态派生、指标格式、空值与比较
- E2E：刷新/返回/前进、快速切站、慢请求、错误重试、保存后取消、反复打开关闭抽屉
- 实际颜色/焦点与键盘记录；屏幕阅读器覆盖情况
- 移动端、缩放、长文案检查
- lint/typecheck/已有相关测试真实执行结果，区分通过、失败、未运行

达到本轮停止条件：五项改进中的批准范围在既有产品内落地，关键任务路径可用，真实数据语义无回退，测试与限制有证据。调色完成、截图好看或单页无横向溢出，都不是完成条件。

## 9. 可访问性标准引用

- [WCAG 2.2 快速参考](https://www.w3.org/WAI/WCAG22/quickref/)
- [1.4.3 文本对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文本4.5:1；符合“大字”定义时3:1。
- [1.4.11 非文本对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)：识别控件及必要图形信息的相邻对比。
- [2.1.1 键盘](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)：功能有键盘可操作方式。
- [2.5.8 最小目标](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：24×24 CSS px 或符合列明例外；本设计建议常用触控目标44px，这是额外的设计选择，不应写成AA统一强制44px。
- [1.4.10 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)：等效320 CSS px宽度下内容可重排，具有必要二维布局的信息有例外。
- [2.4.11 焦点不完全遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)：尤其检查固定顶栏/抽屉/提示。
- [4.1.3 状态消息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)：不抢焦点也能让辅助技术获知适当状态变化。
- [复杂图像文本替代](https://www.w3.org/WAI/tutorials/images/complex/)：图表需要能表达等价信息的描述/表格，不是仅给一个名称。
- [Disclosure 模式](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)：分组展开可用原生语义或正确的展开状态。

以上是实施目标，不是 WCAG 合规声明。认证式结论必须以实际运行页面、全部相关状态和完整评估范围为准。
