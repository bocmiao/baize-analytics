## 修改范围

- 站点选择器改为名称、域名两行，折叠导航独立成按钮；保留原生选择器、键盘操作和手机抽屉。
- 构建时生成 gzip/Brotli；哈希资源长期缓存，HTML 不缓存，主题脚本重新验证。
- 按完整 URL 缓存报表 10 秒，最多 32 条；并发请求合并。手动刷新、写入、会话失效和账号变化有独立失效规则。
- 图表复用实例和画布，首个空配置安全处理；首帧提前应用已选主题。
- Standard 概况的摘要、趋势、地域与主统计并行读取，主统计不再阻塞整个页面。
- 只在有预算限制的 PostgreSQL 统计读取中关闭 JIT，离开时恢复原设置；恢复失败则销毁连接。数据库全局配置、原有超时和读取预算保持原值。

## NAS 实测

| 项目 | 结果 |
| --- | --- |
| 首屏 JS/CSS 原始传输 | 1,625,455 B |
| gzip / Brotli 传输 | 491,002 B / 428,836 B |
| 七天单条统计 SQL，JIT 开 / 关 | 724.5 ms / 18.8 ms |
| 七路冷并发，包括重复统计、摘要与趋势 | 全部不超过 1.95 秒 |

| 原有三个站点数据 | 3,444 条事件，站点及事件摘要前后一致 |

六次统计响应与修复前完整结果对照，稳定指标完全相同；排除随时钟变化的执行元数据和留存成熟状态文案。浏览器刷新到可见摘要约 2 秒，此为一次含浏览器操作开销的观测，不作为稳定 SLA。

## 性能边界

此轮优先修复资源交付、重复请求、图表重建、串行等待，以及统计 SQL 的编译开销。使用 NAS 上的合成数据测量，不将单条 SQL 的加速比例等同于整个产品所有报表的加速比例。首次未缓存的大范围统计仍取决于数据量和服务器负载。
