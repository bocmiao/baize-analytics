# Operational historical namespace backup and restore

The operational CH package now includes all published 028 history manifests and their immutable raw/hourly/daily/vitals rows, streamed into per-manifest NDJSON files in pages of 100. It also streams a PostgreSQL 033 backing fingerprint (published run metadata, effects, original vital samples and relational hour references). The PostgreSQL custom dump taken from the same exported snapshot supplies the actual backing tables. Every package file is SHA-256 checked, fsynced and private; neither application keys nor service credentials are included in this package.

Restore requires a new PostgreSQL database and an explicit, nonexistent `baize_restore_*` ClickHouse database. Existing CH databases are refused. Each archived manifest receives a fresh ID and namespace; its source body checksums are verified before it becomes published in target PostgreSQL. The target PostgreSQL backing fingerprint must exactly match the package. Source namespaces are read only. The current independent deletion journal must extend the package's verified journal prefix. Target startup replays that latest journal, physically removes the precise visitor/identity intervals, rebases surviving historical and relational metadata, enforces current history retention, and rebuilds retained analytics before reporting success. The shell rechecks the live source journal immediately before writing its success marker. A changed journal fails the attempt and retains the isolated target for diagnosis.

The new namespace package is version 2, with explicit schema `028+031+033-through-035+036-carry-v1+037+038-provenance+039-shadow-validation+040-notification-cleanup+041-session-topology-v1+042-manual-search`. Its streaming fingerprint includes published V1/V2 run metadata, effects and original vitals, hour references, and all four 036 carry tables. PostgreSQL restores those rows from the same exported snapshot; the independent fingerprint is checked before historical bodies are published. Unknown migrations, fact versions, partial carry schemas and malformed checkpoint checksums reject. Known version-1 packages remain limited to empty carry and their original fingerprint. This packaging does not activate the prefix reducer or canonical authority.
