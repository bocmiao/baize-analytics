# Relational history backup validation

Signed history packages now include a versioned, SHA-256 checked relational backing section for migration 033: published run metadata, selected event effects, original vital samples and hour references. Capture uses the same PostgreSQL snapshot as the history package, cursor pages of 100, explicit 100,000-row limits and a 128 MiB total backing limit. Packages exceeding these budgets fail; they do not silently omit members.

An empty target imports new run UUIDs and the target aggregation epoch. Run generations retain their relative order; the newest imported run maps to the target processed generation, so a later rebuild wins. Existing backing is reused only after exact checksum equality. Different timezone, privacy or site configuration rejects import instead of interpreting archived hours under a new configuration. Relational history without backing fails closed. Legacy packages containing genuine JSON membership remain compatible.

Executed locally against isolated real PostgreSQL schemas: two tests passed. They prove UV 2 survives run/epoch remapping, original unequal vital values 100/900 survive, and precise deletion of visitor A leaves UV 1 and visitor B's 900 sample. The missing-backing test rejects an empty-UV substitute. Scoped lint and TypeScript checks passed before the latest epoch-fence addition; final repeated checks are recorded separately by the integrator.

This section restores archived 033 queries, not future 036 prefix carry state or a replacement for retained raw source. Full operational PostgreSQL dumps preserve all tables. Independent historical ClickHouse namespace packaging and its installer restore are still being implemented; a fresh restore with published historical namespaces currently refuses to report success rather than erase unique archived detail. The new production Docker wrappers have not yet been exercised with these changes.

History mint snapshot ordering was also exercised against real PostgreSQL and ClickHouse: an actual deletion transaction held the site gate, removed A and rotated its epoch while backup waited on an observed ungranted advisory lock. After commit, backup took a fresh snapshot and rejected the old manifest with `HISTORY_EPOCH_CHANGED`; it did not create a backup file. This test passed. Source mint releases its site gate after snapshot capture/metadata commit, so a subsequent acknowledged deletion can still revoke the pending file through fresh journal/epoch verification. Keeping that gate across file hooks caused two timeout failures in the first run; the failure log is retained. After the fix, both deletion-at-file-hook cases passed. The combined legacy suite still has one obsolete-versus-published expectation under the newer precise history preservation contract; this is recorded as a failure pending the history owner's review.
