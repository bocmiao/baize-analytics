# Canonical daily-salt backup proof

The next operational package signs the canonical manifest with the separately protected `master.v1.key`, using a versioned HMAC domain. The signature covers the original authority epoch, validated daily-column metadata, complete body-file checksums and journal prefix. Credentials and key bytes are never included in the data package.

Daily authority export requires both validated migration metadata and a controlled column seal for every exported event. Restore verifies the signature before trusting that metadata, checks each event's supplied private column proof before publishing its target batch, and remaps the validated authority metadata to the fresh target epoch only after reconciliation. A missing supplied proof cannot fall back to an unrelated target provenance row. Unknown legacy daily events, including a single observed day, are rejected.

History namespace packages use a separate HMAC domain and preserve each raw row's private `columnProof`. Raw pages are validated in batches of 100 before export and before writing the independent target namespace. PG-authoritative daily history requires these row proofs and the signed package; it does not require a ClickHouse cutover header. Existing standalone signed history files receive the same per-page proof check.

Real PostgreSQL/ClickHouse regression verifies standard backup/deletion reconciliation, rejection of unvalidated daily source metadata, refusal of an unsigned daily target package, rejection of wrong-key or altered signed headers, and an authenticated single-day body lacking a column seal. A separate positive case runs controlled producer provenance, full shadow validation, raw-body pruning, signed export, restore into a distinct CH database, target proof import and epoch remapping, then same-transaction alias cleanup. The original CH body is unchanged. Its initial missing aggregation-state fixture failure is preserved; the corrected run passes. Compiled Docker shell entry for this new scope remains pending. No production activation or traffic switch is performed by these tests.

The producer proof ledger is being given an independent site lifetime so ordinary PG raw pruning does not remove column seals. Accepted wire hashes remain in `event_keys` while the corresponding authoritative CH body exists; those keys may be cleared only after its physical retention ACK. Missing retained accepted hashes or column seals fail export safely. Precise proof-ledger deletion and retention lifecycle tests are owned by the privacy adapter work; this package does not claim those lifecycle tests or enable authority activation. A validated authority header alone cannot replace a column seal.
