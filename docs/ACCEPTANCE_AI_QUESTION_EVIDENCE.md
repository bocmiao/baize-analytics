## File boundary and contract

- `packages/contracts/ai-evidence.ts`: strict metric/dimension/filter/date schema; at most 31 inclusive calendar days; server result series, actual storage/version metadata, successful scoped tool traces. Model input cannot contain SQL, table names, arbitrary filters or a site ID. Evidence/chart equality and query-to-series correspondence are validated, including explicit truncation.
- `src/server/ai-evidence.ts`: `readQuestionAggregate(pool,scope,input)` reads only real `stats_daily` preaggregates. It uses a single existing transaction/client with the partition/site gate, checks actual `generation == processed_generation`, and reports epoch/watermark/source. Internal segment visitor sets are unioned for exact UV; no identifiers leave the reader. Filtered day queries retain real daily axes instead of presenting a whole-period total as a day. Missing joint dimensions and daily-salt cross-day UV are unsupported. Zero-session conversion rate is null, with numerator/denominator shown.
- `runEvidenceQuestion({scope,question,authorize,read,respond})`: authorization is mandatory at start, each model turn, every tool call and completion. It accepts at most three turns / three tools per turn. At least one successful authorized `query_analytics` read is required before accepting prose. Pure-content replies, unknown tools, malformed/out-of-scope parameters, duplicate tool-call IDs and unsupported-only results cannot complete a question. Charts come directly from the validated server tool results, never the provider's claimed chart numbers. Context and field sizes are bounded. Tool failures return fixed safe parameter errors; raw internal errors are not copied into model messages.
- `persistQuestionEvidence(client,callId,siteId,evidence)` uses the caller's budget-finalization transaction/client. It checks the site scope and existing question call; it never borrows a second pooled connection while a caller holds locks.
- Forward migration `030_ai_question_evidence.sql`: final traces are kept separately from the original immutable `ai_calls.evidence`. Composite call/site FK rejects cross-site evidence references. Final trace UPDATEs are rejected; site/call deletion cascades remain supported.

The module records factual series separately from model prose. It does not prove that provider prose contains correct interpretations or guarantee model quality. Read source is explicitly PostgreSQL preaggregate; this is not a claim that question tools run entirely on ClickHouse.

Root review found a genuine missing privacy boundary: old completed AI calls and final trace rows survived visitor deletion, and saved-result GET only checked completion status. The earlier24-test result did **not** test this new cache lifetime and is not evidence that the original code was safe after deletion.

It retains monthly `ai_budget` and encrypted connector settings. This intentionally invalidates advice about other visitors at the same site too, because aggregate evidence cannot safely be attributed back to a single deleted person. Questions and suggestions can be generated again from rebuilt facts. Other sites are preserved. Immutable evidence triggers are unchanged: deletion is used, never UPDATE of evidence.
