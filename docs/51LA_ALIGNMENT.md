# 流量工作台：界面与实现范围

这版白泽后台采用白色桌面工作台，报表导航、概况表、日期筛选、图表与明细表的结构参考 51.LA 公开页面。手机端调整导航与报表布局。白泽的采集、鉴权、统计、存储与界面代码由本项目独立实现，展示的是当前白泽实例的数据。

## 运行方式

新增流量报表由 **Node 标准版**提供，能力标记为 `capabilities.trafficReports=true`。Node Lite 和独立 PHP 版保留各自既有功能，本次界面调整不代表三个运行方式的报表、接口或数据库能力已经一致。

| 内容 | 实现范围 |
| --- | --- |
| 概况 | 今日、昨日、昨日同期；5/15/30 分钟活跃访客；本月、总流量和历史峰值按需展开 |
| 流量与内容 | 日/小时、周/月、来源、页面、入口、目录、域名、渠道、环境、地域等真实统计 |
| 访问明细 | 按会话分页、过滤及窗口内访问路径；遵守明细保留与删除规则 |
| 新老访客 | 使用真实首次访问日期；缺少记录保留未知；每日趋势按该日分类 |
| 独立 IP、运营商 | 没有对应采集依据，显示不可用；已有脱敏网段不等于独立 IP |
| 预测 | 当前未提供预测值 |

详细参数、字段和覆盖率规则见 [API 手册](api.md#新流量报表node-标准版)。

## 公开参考与 REA 分析

参考来源包括 [51.LA V6 公开入口](https://v6.51.la/)、[公开帮助文档](https://v6.51.la/help-doc/)和已发布客户端中可读取的导航、列定义与路由声明。桌面页面的实际观察、帮助文档描述和静态代码线索分别记录，未把静态路由字符串当作接口调用成功的证据。

本次使用 [morluto/rea](https://github.com/morluto/rea) 的 `rea-agents 6.8.0` 对选定的两个公开脚本进行静态分析：`app.4cc3fb56.js` 与帮助站点 `index-sgfPN0nQ.js`。本地报告记录了源文件摘要、来源地址、分析范围与未解析项。REA 分析没有执行目标脚本，也没有通过该工具登录目标账户或调用目标私有接口；动态表达式与语义图覆盖仍有限，不能据此声称还原了 51.LA 的服务端算法、权限或完整移动端行为。

研究材料留在本地忽略目录 `.baize/51la-reference/`，包括 `REA_STATIC_REPORT.md`、`REFERENCE_INVENTORY.md`、资源清单与原始证据。第三方 JavaScript、CSS 和证据包没有作为白泽的运行代码打包。白泽使用自己的名称、新生成的白泽头部 Logo 和项目身份，没有移植 51.LA 的 Logo、公司身份或页脚署名。

## 数据边界

所有站点报表沿用白泽的站点权限、删除记录与存储快照。明细接口通过现有事件存储读取，概况和历史统计复用已发布事实及经过校验的汇总来源。

- 时间区间为 `[from,to)`；站点日历按其 IANA 时区计算。完整单日的小时轴补真实零值桶，缺失覆盖不补零。
- UV 按访客集合去重。总跳出率和平均时长按总会话量计算，不取每日比率的简单平均。
- 原始事件过期、明细超限或会话上下文不足时，保留不可用状态。汇总尚存不能恢复已经缺失的逐次访问路径。
- 历史旧小时汇总与事实重叠时，不能证明完整、不重复的数据返回 `overlapping_legacy_history` 和 `null`。历史总量的起点为仍可读取的已发布历史，不声称覆盖没有保存过的数据。
- `daily_salt` 不支持跨日身份统计、新老访客或 IP 网段。未知值与不可用值不替换成零或演示数据。
