# Canonical ingestion: staged verification, authority not activated

The default PostgreSQL collector still accepts actual tracker payloads and preserves event-ID/order conflicts, identity/tombstone checks, event-time daily salt, bot exclusion and input-only IP handling. The collector checks the independent canonical authority while holding the same site/partition gate. Infrastructure adapter registration cannot change authority or override the hard integration-readiness gate. Even a manually set ClickHouse authority returns503 before inserting new receipts while the full integration is not ready.

`canonical-ingest.ts` provides adapter registration, guarded target resolution and publication. The prepared canonical branch accumulates only sanitized `StoredEvent` bodies (no raw IP, secrets, URL query/hash or unmasked replay). Daily-salt null truncated IP is omitted from the canonical dimensions; standard anonymized IP remains a string. It omits PG `events` and `event_data` body writes while retaining receipt/order/outbox metadata in the existing transaction. Adapter publication writes a unique immutable CH attempt, verifies reread SHA/count, and writes PG manifest/member metadata before the caller commits. Successful publication itself is not202. Failed CH body/checksum/manifest publication raises503 and the transaction rolls back; a post-upload PG failure can leave CH orphan rows, but only committed exact manifest attempts are visible. Duplicate key receipts require a current-epoch manifest member or an already stored matching revenue order, not an arbitrary key alone.

The collector independently refuses canonical identify/user_id/replay operations: identity still updates historical PG payloads and replay still has PG replay-chunk dependencies. `CANONICAL_ACTIVATION_READY` stays false, activation/pruning stay disabled, and the new store registry is not installed by application startup yet. Therefore **production canonical202 and outbox-after-pruning are not accepted as complete**. Complete read/deletion/recovery/identity/replay integration and authority activation verification are still required. The publication helper tests are not a bypass of this production gate.
