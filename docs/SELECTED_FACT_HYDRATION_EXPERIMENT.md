# Historical selected TEMP projection experiment (withdrawn)

At experimental commit 267f660, the query path was enabled only by `BAIZE_SELECTED_FACT_HYDRATION=1`. The production default is complete hydration. The benchmark accepts `BAIZE_PERF_SELECTED=0` or `1` and records the resolved switch; all other schedule, queue, concurrency and drain parameters are unchanged. Compare both switches on the same immutable source, not a different 059 migration baseline.

Every original immutable batch still streams and verifies its entire receipt, count, body hash and producer HMAC before any row is filtered. After authentication, only read-only statistics TEMP rows may be projected onto the current session contribution owner or the existing no-owner legacy hourly fallback. Empty retired owners suppress old rows. Vital samples use the authenticated envelope session identity, not a potentially filtered effects join. Unmigrated PostgreSQL identity writes remain complete.

Rebuild, authority transition, repair, backup and unknown complete-source consumers do not opt into partial TEMP. A selected context cannot satisfy a request for complete rows. Proof-only callbacks that consume no TEMP rows may explicitly inherit an already authenticated bound context; unbound proof requests still require complete authentication. Their source, coverage, closure and fence guards remain unchanged. Standalone retention honors the experimental switch; nested retention explicitly honors its bound projection.

Counters `authenticatedRows` and `selectedHydratedRows` refer only to facts `temp_fill` observations and are cumulative across calls, not unique events or all authentication work. Original body authentication counters stay intact. Zero and unmeasured null are distinct. These counts, adapter times and whole-operation walls must not be added as independent elapsed time.

Validation history is in PERFORMANCE_INCREMENTAL_056_VALIDATION.md. An earlier full unit run and eight HTTP cases failed and remain archived. The corrected frozen directory passed 355 unit tests and ten actual PG/CH regressions with zero skips. The bridge oracle includes superseded A, unchanged B, no-owner fallback, empty retirement and mixed PostgreSQL identity/vitals. A missing superseded body still causes rejection before a selected result. No performance improvement or production capacity is claimed before the fixed A/B measurement.

## Maintenance and delivery decision

The same-source 300 pair demonstrated no net benefit for the fixed new-visitor load: selected authentication and TEMP insertion both remained 8506 rows. This is not an accepted capacity optimization. Keeping this experiment entails two runtime helper modules, changes to eight existing runtime modules (read-context provenance, explicit consumers and proof-only contracts), extra metrics and dedicated regression coverage. Future owner/legacy fallback/vital or schema changes would need to preserve both modes. That cost is real even with the switch disabled.

The production experiment has now been withdrawn: runtime helpers, opt-in consumers, benchmark switch and dedicated experimental tests were restored to the pre-experiment implementation. Complete authenticated hydration remains the sole supported path. The historical commits and A/B evidence remain available; the flag described above is not a current configuration option. Its isolated fixture can exclude superseded rows, but that is correctness evidence, not measured production performance. It must not silently become another default-off feature presented as a completed speedup.

The recoverable project checkpoint `/workspace/baize-checkpoints/selected-no-benefit-267f660-retired/` contains the six retired helper/test files and copies of fourteen restored files with a checksum manifest (122,888 bytes). This is archival preservation, not a claim of disk space reclaimed. No 059 migration or retirement-origin protection was reverted. The separate transaction-local closure-selection candidate is unrelated to this withdrawn query projection.

Withdrawal validation: full unit directory 339 PASS / 0 FAIL / 0 SKIP, typecheck and diff checks EXIT 0. This working-tree directory also contained the default-off closure candidate units; that candidate is not included in the withdrawal commit. These are local checks, not a new complete integration/browser/image acceptance.
